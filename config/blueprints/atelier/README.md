# atelier blueprint

Runs [Atelier](https://github.com/aincient-labs/atelier-cms), adapted from the
upstream appliance topology in `docker/compose.yaml` and `docker/edge.conf` of
`aincient-labs/atelier-cms` at tag `v0.24.0` (commit d24da75). The upstream
`docker/.env.example` documents the variables.

## Services

| Upstream | Here | Notes |
|---|---|---|
| `db` (`pgvector/pgvector:pg16-trixie`) | kept | Password generated per app (`DB_PASSWORD`) instead of the upstream default `aincient` |
| `app` (`ghcr.io/aincient-labs/atelier-cms`) | kept | Image from the blueprint's allowlist (`IMAGE`), no `build:` section, no `host.docker.internal` mapping |
| `edge` (`nginx:1.30-alpine-slim`, `edge.conf`) | kept | Public service on port 80; Traefik in front instead of the published port 41221 |
| `updater` (one-click upgrade sidecar) | dropped | It mounts `/var/run/docker.sock`, which is root on the Scotty host. Upgrade through Scotty instead: add the new pinned tag to `images` in `blueprint.yaml`, then re-create the app with `--image <tag>` |

## Volumes

`db-data` (Postgres), `files` (Drupal public files), `private` (snapshots,
`INITIAL_ADMIN_PASSWORD`; shared read-only with `edge`). Upstream's
`upgrade-signal` is dropped with the updater. Destroying the app, including a
TTL destroy, removes the volumes, so create Atelier apps with `--ttl forever`
and without `--destroy-on-ttl`.

## Environment

| Variable | Source |
|---|---|
| `HASH_SALT` | generated by Scotty (`hex32`), never returned by the API |
| `DB_PASSWORD` | generated by Scotty (`hex32`), never returned by the API |
| `AINCIENT_TRUSTED_HOSTS` | derived by Scotty from the app's hosts (`app.domain_pattern`, e.g. `^edge\.demo\.example\.com$`); upstream treats an empty value as "accept any host" |
| `ADMIN_PASS` | optional caller parameter; empty means Atelier generates one into `private/INITIAL_ADMIN_PASSWORD` |
| `AINCIENT_REVERSE_PROXY` | fixed `1`: edge is the only way in, so its forwarded headers are trusted |
| `AINCIENT_FAST_RESTART` | fixed `1`, the upstream default |

Only pinned tags go into `images`, never `:latest`: a mutable tag would change what an app runs without any change to the blueprint. When moving to a newer upstream tag, diff its `docker/compose.yaml` and
`docker/edge.conf` against this blueprint; `edge.conf` must match the image
version.
